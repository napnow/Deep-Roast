# Infinite Canvas Persistence Implementation Plan

**Goal:** Persist verified edit ancestry and account-scoped canvas layouts while preserving existing single-image and mobile workflows.

**Architecture:** Bind each claimed parent to an authenticated user's actual edit target before generation; write lineage with successful image records. Save bounded layout snapshots per user using revision-based compare-and-swap; restore saved nodes with owned image metadata even when outside the recent-history window. Render only verified ancestry among present nodes.

**Tech Stack:** Next.js route handlers, Drizzle/PostgreSQL, React Flow, node:test and Playwright.

## Constraints

- Do not backfill or invent ancestry for old images. Deleting a parent must not delete children or their recorded source IDs.
- Keep original image/edit paths, authentication, credits, idempotency, mobile and single-image mode intact.
- Reject unowned source/layout images, malformed payloads and stale revision writes; never expose another user's image.
- Isolated database and browser verification before any deployment; do not build on production.

## Tasks

1. Add nullable lineage columns and user-scoped layout table with migration, baseline and contract tests.
2. Verify actual target ownership, capture authorized input, write parent/group metadata per successful variant and return it to the client; test target mismatch, old roots and batches.
3. Build authenticated load/save API with atomic revision checking and ownership checks; preserve old saved nodes beyond the history page and handle deleted records.
4. Render saved nodes and confirmed edges, autosave deliberate position/viewport changes, expose save/conflict/retry status and preserve keyboard access.
5. Run migration/bootstrap, source authorization, conflict, isolation, browser, type and regression tests; review outstanding crash/idempotency and operational limitations.
