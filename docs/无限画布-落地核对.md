# 无限画布落地核对（2026-11-16）

## 目标与基线

保留现有单图工作台、输入区和设置区；桌面提供可展开的无限画布，以较大的图片卡片展示作品，支持平移、缩放、移动和选择。手机端沿用现有布局。线上当前 release 为 `20261116-image-canvas`，构建 ID 为 `EvlQJzqtpNy8dOG9CZ3dX`；ResultCanvas、studio-preview.css、数据库 schema 和 package.json 的 SHA-256 与本地工作区一致。此核对仅覆盖上述文件，并不证明全部文件一致。发布目录无 Git 元数据，不能据此断言线上 commit。

## 需要补齐

- 版本关系尚未实现：现有 `ImageRecord` 没有来源 ID；原型中的连线不能用于真实历史。新编辑成功时服务端需验证来源属于当前用户并持久化父子关系；批量、重试、幂等、删除父图需覆盖。旧图不回填，旧图可成为新版本树的根。
- 区分作品版本树与画布布局：保存节点位置、视角和选择状态不能代替服务端版本关系；移出画布不删除作品。涉及用户隔离、跨设备恢复、并发更新和异常保存提示。
- 图片使用缩略图，原图按需加载；大量节点需要视口裁剪或分批渲染。不能声称节点数或并发无限，需依据测试确定合理边界。
- 画布平移、节点拖动和缩放须提供可发现的按钮及键盘替代操作；处理触屏、滚轮、缩放中心、边界、焦点和 reduced motion。
- 生成中、失败、批量部分成功和取消状态必须保留原有行为；继续编辑选中节点需复用现有鉴权和计费链路。
- 变更前重新核对迁移机制、实际表结构、备份与回滚，隔离环境验证；不在生产机构建。正式上线前进行安全、性能、交互及跨端验收。

## 实施顺序

1. 提取并测试画布坐标变换，让缩放锚点和拖动行为可独立验证。
2. 在真实工作台接入可展开画布，使用实际作品，不显示未记录的来源线；增大节点图片，保留单图模式。验证键鼠和移动端不回归。
3. 实施 `创作版本记录-落地方案.md` 中的服务端来源关系、鉴权与迁移，在隔离环境完成测试后接入真实连线。
4. 设计并实现有用户隔离的布局持久化、恢复和冲突处理；最后进行全流程与负载测试。

每一步未完成不得宣称完整功能已交付；不会在没有用户要求时部署或修改生产数据。
