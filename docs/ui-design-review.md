# 深焙 Deep Roast · 界面设计审查报告

> 审查日期：2026-07-31
> 审查范围：`src/app/layout.tsx`、`src/app/page.tsx`、`src/app/globals.css`、`src/components/` 核心组件
> 审查视角：UI 设计系统、可访问性（WCAG AA）、响应式、交互一致性

---

## 一、现有设计值得肯定的基础

在指出问题之前，先明确做得好的部分——这些是新方案应该保留的资产：

| 维度 | 现状 | 评价 |
|------|------|------|
| 品牌主题 | "深焙工坊"——炭黑/石米/焦糖配色，Fraunces 衬线 + Manrope 无衬线 | 品牌识别度高，情绪一致 |
| Design Token | `globals.css` 定义了完整的 CSS 变量体系（颜色/阴影/圆角/间距） | 基础设施齐全 |
| 暗色模式 | 双主题 token + `prefers-color-scheme` + localStorage 持久化 | 实现完整 |
| 主题化动效 | 蒸汽升腾、烘焙完成、余烬呼吸等命名贴题 | 有记忆点 |
| 无障碍基础 | `prefers-reduced-motion` 支持、`focus-visible` 全局样式 | 已有关注意识 |

**结论：底子是好的，问题出在"执行层一致性"和"可用性覆盖"上。**

## 二、六大问题域详析

### 问题 1：可访问性不达标（严重）

这是影响最广、触及 WCAG AA 红线的问题。

#### 1.1 文字对比度不足

| 颜色组合 | 浅色模式值 | 估算对比度 | WCAG AA 要求 | 状态 |
|----------|-----------|-----------|-------------|------|
| text-muted / bg-surface | `#8a8175` / `#f2efe8` | ~2.9:1 | 4.5:1（正文） | 不达标 |
| text-secondary / bg-surface | `#5a5248` / `#f2efe8` | ~5.4:1 | 4.5:1 | 勉强达标 |
| accent / bg-surface | `#9a5528` / `#f2efe8` | ~3.8:1 | 4.5:1（小字） | 不达标 |
| text-muted / bg-elevated | `#8a8175` / `#faf8f4` | ~2.8:1 | 4.5:1 | 不达标 |

**代码位置**：`globals.css:18`（`--text-muted: #8a8175`）、`globals.css:19`（`--accent: #9a5528`）

**影响**：`--text-muted` 被大量用于副标题、时间戳、模型名、placeholder 等次要信息，几乎遍布全应用。次要信息不等于可以看不清。

**改进方向**：
- 将 `--text-muted` 浅色值加深至 `#6b6358` 左右（对比度 ~4.6:1）
- 焦糖强调色用于小字时加深至 `#7a3f1f`，或仅用于 ≥14px 的中粗文字
- 引入自动化对比度检查（如 eslint-plugin-contrast-ratio）

#### 1.2 触摸目标过小

| 元素 | 当前尺寸 | 文件位置 | 推荐尺寸 |
|------|---------|---------|---------|
| Sidebar 删除按钮 | `w-5 h-5`（20px） | `Sidebar.tsx:87` | ≥44×44px |
| Header 设置按钮 | 约 28×28px | `Header.tsx:113` | ≥44×44px |
| 积分"低"徽章 | ~16×12px | `Header.tsx:168` | 不应作为独立交互区 |

**改进方向**：所有可点击元素最小命中区域 44×44px，可通过 `padding` 扩大点击区而不增大视觉尺寸。

#### 1.3 字号低于可读门槛

多处使用 `text-[10px]`、`text-[9px]`：
- `Header.tsx:67` — "Deep Roast" 标签 `text-[10px]`
- `Header.tsx:168` — 积分"低"徽章 `text-[9px]`
- `Sidebar.tsx:98` — 对话元信息 `text-[10px]`
- `ChatView.tsx:91` — "思考过程" `text-[11px]`

**改进方向**：最小正文 12px，最小标注 11px，建立语义化字号 scale（见问题 4）。

### 问题 2：响应式完全缺失（严重）

`globals.css` 共 906 行，**没有任何一个 `@media (min-width:)` 响应式断点**（只有 `prefers-reduced-motion` 和 `prefers-color-scheme`）。

#### 2.1 固定宽度组件

| 组件 | 固定值 | 文件位置 | 移动端问题 |
|------|--------|---------|-----------|
| Sidebar | `w-64`（256px） | `Sidebar.tsx:24` | 占据手机近半屏宽，且不可折叠 |
| ImageGenView 三栏 | 输入列 + 结果 + 历史并排 | `ImageGenView.tsx:91-126` | 窄屏严重挤压，每栏不可用 |
| Header 元素 | 8 个横排无收缩 | `Header.tsx:48-181` | 窄屏溢出/重叠 |
| ChatView 内容 | `max-w-3xl` 居中 | `ChatView.tsx:44` | 外层无 padding 收缩 |

#### 2.2 改进方向

建立标准断点体系并贯穿全部组件：

```
sm: 640px  — 手机竖屏 → 单栏 + 抽屉式 Sidebar
md: 768px  — 平板     → 双栏，Sidebar 可折叠
lg: 1024px — 桌面     → 三栏（图片模式）/ 双栏（文本模式）
xl: 1280px — 大屏     — 优化留白
```

### 问题 3：Header 信息过载（中等）

`Header.tsx` 在 52px 高的单行内塞入 8 个功能元素：

```
[Logo] [模式切换] [模型选择] [公告铃铛] [设置] [签到] [积分钱包] [用户菜单]
```

#### 3.1 问题分析

- **视觉焦点分散**：8 个同级元素，用户找不到"主操作"在哪
- **低频功能挤占注意力**：签到、积分这类低频功能与设置、模型选择同级
- **闪烁动效制造焦虑**：积分低时 `animate-pulse-soft` 持续闪烁（`Header.tsx:168`），违反"动效应服务信息而非制造压力"原则

#### 3.2 改进方向

- 将签到、积分钱包、设置等**低频功能收纳进用户菜单**（下拉）
- Header 只保留：Logo + 模式切换 + 模型选择 + 用户头像
- 积分低提醒改为静态角标，移除持续闪烁

---

### 问题 4：设计系统执行不统一（中等）

虽然定义了 Design Token，但执行层松散：

#### 4.1 内联 style 与 Tailwind 混用

几乎所有组件都用 `style={{ background: "var(--accent)" }}` 而非语义类：

```tsx
// Header.tsx:84-93 — 模式切换按钮
style={{
  background: "var(--bg-elevated)",
  color: "var(--text-primary)",
  boxShadow: "var(--shadow-sm)",
  border: "1px solid var(--border-strong)",
}}
```

**影响**：主题切换、深浅色适配要逐个排查内联样式，维护成本高；无法利用 Tailwind 的响应式前缀。

#### 4.2 圆角值混乱

同时出现：`rounded-lg`、`rounded-xl`、`rounded-2xl`、`rounded-[10px]`、`rounded-br-md`、`rounded-bl-md`——而 `globals.css` 已定义 `--radius-sm/md/lg/xl`。Token 形同虚设。

#### 4.3 字号用方括号任意值

`text-[12.8px]`、`text-[13px]`、`text-[10px]`、`text-[11px]`、`text-[15px]`、`text-[9px]`——完全没有语义化 scale。

#### 4.4 间距不遵循网格

`px-5`、`px-6`、`px-4`、`p-3`、`p-1.5`、`gap-2.5`、`gap-1.5` 混用，不遵循 4pt/8pt 网格。

#### 4.5 改进方向

- 把 token 暴露为 Tailwind 主题配置（`tailwind.config` 或 v4 的 `@theme`）
- 建立语义类：`.btn-primary`、`.surface-card`、`.text-caption` 等
- 字号 scale：`text-xs(12) / text-sm(13) / text-base(14) / text-md(16) / text-lg(18) / text-xl(20) / text-2xl(24) / text-display(30)`

### 问题 5：交互体验断裂（中等）

#### 5.1 原生 confirm() 破坏一致性

`Sidebar.tsx:85`：
```tsx
if (confirm(`删除对话「${conv.title}」？`)) onDelete(conv.id);
```

浏览器原生灰框与深焙主题完全割裂。应替换为自定义确认弹窗（可复用现有 Toast/Modal 体系）。

#### 5.2 聊天消息无操作

`ChatView.tsx` 的消息气泡只有展示，**没有复制、重新生成、编辑**等操作。对 AI 对话产品，这些是核心交互。

#### 5.3 空状态缺少引导

`ChatView.tsx:46-66` 空状态只有"慢火，把想法焙透"文案，没有：
- 示例 prompt 快捷按钮
- 引导用户第一步的行动召唤

#### 5.4 缺少骨架屏

加载时只有三个跳动圆点（`ChatView.tsx:186-199`），内容区大片空白。应改为骨架屏保持布局稳定。

---

### 问题 6：视觉层次模糊（轻微）

#### 6.1 glass-neon 过度使用

Header、按钮、模式切换、Logo 图标全都有 `glass-neon`。**当所有东西都"发光"时，就没有东西是突出的**——视觉重点失效。

#### 6.2 浅色模式背景色差极小

| Token | 值 | 亮度 |
|-------|-----|------|
| `--bg-root` | `#e6e2d9` | ~89% |
| `--bg-surface` | `#f2efe8` | ~94% |
| `--bg-elevated` | `#faf8f4` | ~98% |
| `--bg-canvas` | `#ebe7de` | ~92% |
| `--bg-sidebar` | `#ddd8ce` | ~86% |

五个层次亮度差仅约 5-12%，肉眼几乎无法区分层级。深色模式反而区分度更好。

#### 6.3 改进方向

- 拉大浅色模式各层亮度差至 ≥8%
- `glass-neon` 仅用于 1-2 个真正需要强调的元素
- 明确"主操作/次操作/容器"三档视觉权重

## 三、改进优先级建议

| 优先级 | 问题 | 工作量 | 理由 |
|--------|------|--------|------|
| P0 | 可访问性对比度 | 小（改 token 值） | 触及红线，影响所有用户 |
| P0 | 触摸目标尺寸 | 小（加 padding） | 移动端可用性硬伤 |
| P1 | 响应式断点 | 中（重构布局） | 无移动端适配=流失用户 |
| P1 | Header 信息架构 | 中（重组布局） | 影响首屏体验 |
| P2 | 设计系统统一 | 大（渐进重构） | 长期维护成本 |
| P2 | 交互体验补全 | 中（加功能） | 产品完整度 |
| P3 | 视觉层次优化 | 小（调 token） | 锦上添花 |

---

## 四、总结

深焙的**设计意图和品牌表达是出色的**——"深焙工坊"的炭石焦糖主题、主题化动效、完整的 token 基础设施，都说明设计者有审美和体系意识。

问题集中在**执行层**：token 定义了但没用起来、响应式完全空白、可访问性细节缺失、交互断裂。这些都是"最后一公里"的打磨工作，不需要推翻重来，而是沿着现有体系补全。

建议按 P0 → P3 顺序推进，先解决对比度和触摸目标（改动小、收益大），再攻响应式和 Header 重组，最后渐进式统一设计系统。
