# 深焙工作台与管理台 UI 重构设计

**日期**：2026-08-20

**状态**：已确认，待实施计划

**目标**：在保留现有品牌视觉、业务功能、数据模型和主要 API 行为的前提下，重构登录后的图片创作工作台、对话工作区和管理员控制台。图片生成是产品主功能，桌面网页是主要使用场景。

## 1. 背景与问题

当前工作台已经具备文生图、图生图、提示词反推、对话、图片历史、积分、公告和管理能力，但界面逐步叠加功能后出现以下问题：

- 顶栏同时承担模式、模型、签到、积分和账户入口，主次不够明确。
- 文生图、图生图和反推以临时展开面板组织，切换时缺少稳定的创作心智模型。
- 桌面三栏虽然完整，但中央结果区、输入区和历史区之间的职责还不够清晰。
- 对话与图片创作共享过多外壳约束，两个工作区互相迁就。
- 管理员“运营总览”同时承载统计、站点设置、公告、打赏、风格库和风格测试，信息架构混杂。
- 管理员侧栏既像一级导航，又像用户列表；用户详情的普通操作与危险操作并列。
- 许多辅助信息使用 9–11px 字号，卡片和强调元素过多，导致视觉细碎。

## 2. 目标与约束

### 2.1 目标

- 登录后默认进入图片创作，并让用户更快完成第一次生成。
- 建立“左侧控制、中央创作、右侧管理结果”的稳定桌面工作台。
- 将文生图、图生图和反推整合为同一创作工具的三种模式。
- 将对话设计为独立工作区。
- 将管理台拆分为职责明确的一级模块。
- 保留“深焙工坊”的品牌气质，同时减少视觉噪音并统一组件语言。
- 分阶段实施，每个阶段结束时保持项目可运行。

### 2.2 约束

- 桌面网页优先，手机端保证核心流程可用。
- 保留当前炭黑、石米、焦糖配色，以及 Fraunces 与 Manrope 字体组合。
- 除管理员代管用户 API Key 外，不改变现有后端业务和 API 行为。
- 保留现有 Zustand 状态、生成逻辑、积分逻辑、对话逻辑和图片历史数据，按新组件边界重组。
- 不在本次重构中增加新的生成参数或依赖后端的新生图能力。

## 3. 方案选择

### 3.1 采用方案：创作工作室

图片创作使用三栏桌面工作台：左侧创作控制台、中央结果画布、右侧历史与详情。顶栏只保留全局操作。该方案最符合生图为主功能、桌面优先和高级工具逐步扩展的要求。

### 3.2 未采用方案

- **登录后仪表盘**：入口清晰，但每次生成前多一步，不符合生图为绝对主功能的定位。
- **单列极简流**：易上手，但图生图、批量、风格和反推等高级能力会集中挤进抽屉，桌面效率不足。

## 4. 全局信息架构

```text
用户工作台
├── 图片创作（默认）
│   ├── 文生图
│   ├── 图生图
│   └── 反推提示词
├── 对话
├── 钱包与签到
├── 公告与账户设置
└── 管理控制台入口（仅管理员）

管理员控制台
├── 运营总览
├── 用户管理
├── 站点与内容
└── AI 能力
```

## 5. 图片创作工作台

### 5.1 桌面骨架

```text
┌────────────────────────────────────────────────────────────┐
│ 深焙   [图片创作] [对话]                       积分   账户 │
├──────────────┬──────────────────────────┬──────────────────┤
│ 创作控制台   │       主结果画布         │   历史 / 详情    │
│ 约 320px     │         自适应           │   约 300px       │
│              │                          │   可折叠          │
└──────────────┴──────────────────────────┴──────────────────┘
```

- 左侧负责模式、输入和参数。
- 中央只负责空状态、生成状态、错误状态和结果展示。
- 右侧负责查找历史作品、查看元数据和执行作品操作。
- 窗口宽度不足时，右侧面板变为覆盖式抽屉。
- 右侧折叠偏好保存在浏览器本地。

### 5.2 左侧创作控制台

顶部使用稳定的模式切换：文生图、图生图、反推。当前模式的主要操作固定在面板底部。模型、比例、风格和数量归入左侧，不再占用全局顶栏。

通用规则：

- 三种模式分别保存草稿，切换不会清空提示词、参考图或参数。
- 正在生成时可以浏览其他模式，但同一时间只能提交一个生成任务。
- 切换左侧模式不会取消任务，也不会让中央当前结果消失。
- 次要技术参数默认收进“高级设置”。
- 生成按钮显示图片数量和预计积分成本。

### 5.3 文生图流程

顺序固定为：

1. 提示词输入
2. 常用风格
3. 图片比例
4. 生成数量
5. 高级设置（包含模型）
6. 生成按钮

空输入时提供少量示例提示词。点击示例后填入输入框，用户仍可继续编辑。按钮文案明确展示成本，例如“生成 4 张图片 · 20 积分”。

### 5.4 图生图流程

顺序固定为：

1. 上传参考图
2. 修改要求
3. 风格选择
4. 比例与数量
5. 生成按钮

参考图使用横向缩略图列表，明确显示当前数量和上限。未填写修改要求时，界面说明默认行为是生成相似变体。上传参考图后不再展开独立的大型临时面板。

### 5.5 反推提示词流程

```text
上传图片 → 分析提示词 → 编辑结果 → 带入文生图
```

分析完成后提供“带入文生图”“复制提示词”“重新分析”。“带入文生图”是主操作，点击后切换模式并保留分析结果。

## 6. 中央结果画布

画布只处理四种状态：

### 6.1 空状态

- 使用低强度的“深焙”品牌符号。
- 明确提示用户在左侧描述画面。
- 可提供最近一张作品入口，但不在画布铺开完整历史。

### 6.2 生成状态

- 按选择的图片比例显示骨架占位。
- 展示工作 Orb、真实耗时和停止操作。
- 不显示后端无法提供的虚假百分比。

### 6.3 成功状态

- 单图居中并尽可能利用画布空间。
- 当前会话批量结果使用双列网格；刷新后无需恢复临时批次分组。
- 点击图片进入沉浸式预览。
- 图片附近只保留下载、复制提示词和继续编辑等高频操作。
- 模型、尺寸和时间等技术信息放在右侧详情。

### 6.4 失败状态

- 保留原提示词与参数。
- 区分网络错误、余额不足和服务错误。
- 提供“使用相同参数重试”。
- 失败任务不进入图片历史。

## 7. 历史与详情面板

右侧包含“历史”和“详情”两个 Tab。

### 7.1 历史

- 使用两列缩略图网格。
- 按今天、昨天和更早分组。
- 支持在已加载记录中按提示词搜索。
- 支持前端筛选全部、文生图和图生图。
- 当前图片使用焦糖色描边。
- 删除放入图片更多菜单，并保留二次确认。

### 7.2 详情

展示完整提示词、创建时间、模型和图片尺寸，并提供：

- 复制提示词
- 复用参数
- 进入图生图
- 下载
- 删除

“复用参数”恢复提示词、比例和模型；“进入图生图”将当前图片作为参考图。

## 8. 全局顶栏与账户入口

顶栏高度为 54–56px，只承担全局操作：

```text
深焙   [图片创作] [对话]                         积分   账户
```

- 首次登录默认进入图片创作。
- 后续可在本地记住最后工作区，但不改变默认主功能定位。
- 积分按钮打开钱包、签到和积分流水。
- 模型、签到按钮和管理设置不再直接平铺在顶栏。

账户菜单分组为：

```text
账户：修改密码、API 接入
站点：公告、主题设置
管理：管理控制台（仅管理员）
退出登录
```

## 9. 对话工作区

对话使用独立双栏布局：

```text
┌──────────────┬────────────────────────────────┐
│ 对话列表     │            对话内容            │
│ 新建、搜索   │                                │
│ 历史记录     │         底部固定输入框          │
└──────────────┴────────────────────────────────┘
```

- 左栏约 260px，顶部固定“新建对话”。
- 支持在已加载对话中搜索标题。
- 对话按今天、最近 7 天和更早分组。
- 重命名和删除进入更多菜单。
- 正文最大宽度约 800px。
- 用户消息可保留气泡；AI 回复改为更自然的文档式排版。
- 推理内容默认折叠。
- 输入框固定底部，并展示发送、停止和积分成本。
- 图片创作与对话分别保留输入与滚动位置，不共享侧栏和右侧历史面板。

## 10. 管理员控制台

### 10.1 一级导航

```text
深焙管理台

运营总览
用户管理
站点与内容
AI 能力

返回工作台
```

侧栏约 220px，不再长期展示完整用户列表。移动端改为抽屉。

### 10.2 运营总览

只展示站点状态和关键指标：

- 用户总数
- 图片生成数量
- 累计签到积分
- 累计消耗积分
- 封禁用户提醒
- 注册是否开放
- 打赏是否开启

总览不直接承载编辑表单；状态项跳转到对应管理模块。

### 10.3 用户管理

默认使用数据表展示用户名、状态、积分、对话数、图片数和最近活跃时间。顶部提供前端搜索、状态筛选、角色筛选和最近活跃排序。

点击用户进入独立详情视图：

```text
用户管理 / 用户名

[概况] [图片] [对话] [积分流水] [API Key]
```

调整积分和重置密码属于常规操作。封禁和永久删除放入独立危险区域，与普通按钮隔离。

### 10.4 站点与内容

内部使用“基础设置、公告、打赏”三个 Tab。每个 Tab 只展示一种管理任务，避免页面纵向堆叠全部表单。

### 10.5 AI 能力

内部使用“模型配置、风格库、风格测试”三个 Tab。现有管理员模型配置入口迁移至此。风格库和风格测试属于同一模块，但不同时展开。

## 11. 管理员代管用户 API Key

该能力是本次重构中唯一允许的后端扩展。

### 11.1 管理界面

API Key Tab 展示：

- 名称
- Key 前缀
- 状态
- 成功生成调用次数
- 累计消耗积分
- 最近使用时间
- 创建时间

管理员可以代用户创建、启用、停用和删除 Key。明文 Key 只在创建成功后展示一次；关闭弹窗后无法再次查看。

### 11.2 管理员接口

```text
GET    /api/admin/users/:userId/api-keys
POST   /api/admin/users/:userId/api-keys
PATCH  /api/admin/users/:userId/api-keys/:keyId
DELETE /api/admin/users/:userId/api-keys/:keyId
```

所有接口必须验证管理员身份，并验证 Key 属于路径中的目标用户。创建数量继续遵循每名用户最多 10 个 Key。

### 11.3 用量数据

在现有 API Key 记录上增加：

- 成功生成调用次数
- 累计消耗积分

通过 API Key 发起的图片生成成功并完成扣分后，更新这两个字段和最近使用时间。失败请求不累计次数和积分。本阶段不保存完整调用明细；未来需要逐次审计时再增加独立日志表。

### 11.4 安全规则

- 数据库继续只保存 Key 哈希和前缀，不保存明文。
- 管理员不能查看已创建 Key 的完整明文。
- 用户被封禁后，其 Key 自动不可使用，但记录保留。
- 停用与删除是不同操作：停用可恢复，删除不可恢复。
- 删除需要明确二次确认。

## 12. 视觉与组件规范

### 12.1 颜色与层级

- 保留石米浅色、炭黑深色和焦糖强调色。
- 焦糖色只用于主按钮、当前选中项和生成状态。
- 红色只用于停止、停用、封禁和删除。
- 纹理和光斑保留在背景区域，输入、表格和长文本区域降低纹理干扰。

### 12.2 字体与尺寸

- Fraunces 用于品牌和展示标题，Manrope 用于操作界面。
- 正文不低于 13px；主要输入为 14–16px；辅助标签最低 11px。
- 普通按钮高度为 36–40px，核心生成按钮为 44px。
- 面板圆角统一为 12px，弹窗和大型容器为 16px。

### 12.3 图标、阴影与动效

- Emoji 图标替换为统一的 SVG 图标。
- 普通分区主要依靠背景与边框，阴影用于浮层、弹窗和选中作品。
- 常规动效控制在 150–250ms。
- 保留生成 Orb 和关键状态动画，减少大面积页面模糊与缩放。
- 继续尊重 `prefers-reduced-motion`。

## 14. 状态与数据流

- 全局认证、积分、配置、生成状态、历史和对话继续由现有 provider/store 管理。
- 三种创作模式的草稿在前端状态中分别保存。
- 当前会话的批量结果分组可以是临时 UI 状态，不要求数据库持久化。
- 搜索、筛选、分组和排序优先在已加载数据上完成，不新增 API。
- 管理台一级模块可使用前端状态切换；是否映射为独立 URL 在实施计划中按当前 Next.js 路由约束确定，但不得影响浏览器返回行为。
- 右侧面板折叠状态、主题和最后工作区可使用 localStorage 保存。

## 15. 错误处理与反馈

- 全局非阻塞结果统一使用 Toast。
- 表单字段错误就近显示，不只依赖 Toast。
- 删除、封禁和停用等危险操作使用统一确认对话框，不使用浏览器原生 `confirm`。
- 加载失败保留旧数据并提供重试，不将内容直接清空。
- 创建 API Key 成功后必须要求用户确认已经复制明文，再允许关闭弹窗。
- 未保存的管理表单离开当前模块前给出提示。

## 16. 响应式与可访问性

- 重点验收 1440px、1280px 和 1024px 桌面宽度。
- 小于工作台完整宽度时，右侧历史变为抽屉；左侧创作面板保持核心功能可用。
- 手机端使用顶部菜单和底部创作输入，保留生成、查看、下载和历史核心流程。
- 手机端底部控件同时处理软键盘和 `safe-area-inset-bottom`。
- 所有图标按钮提供可读 `aria-label`。
- 模式、Tab、菜单和弹窗支持键盘操作和清晰的焦点样式。
- 文字与背景对比度按 WCAG AA 目标检查。

## 17. 实施阶段

1. 修复当前构建依赖，整理设计 Token 和共享基础组件。
2. 建立新版顶栏、AppShell 和三栏工作台骨架。
3. 重构文生图、图生图、反推和中央结果画布。
4. 重构历史详情面板和对话工作区。
5. 建立新版 AdminShell、一级导航和四个管理模块。
6. 增加管理员 API Key 管理、最小管理员接口和聚合用量字段。
7. 完成响应式、键盘操作、可访问性、性能和回归验证。

每个阶段都必须保持项目可构建、核心流程可运行，并避免将多个阶段的大范围重写合并成一次不可验证的提交。

## 18. 测试与验收

### 18.1 自动验证

- TypeScript 与生产构建通过。
- ESLint 通过。
- 现有服务层测试继续通过。
- 为管理员 API Key 权限、所有权校验、状态切换、配额和用量累计增加测试。
- 为关键前端状态转换补充组件或逻辑测试：模式草稿保留、生成任务保持、历史选择和参数复用。

### 18.2 人工验收

- 首次登录默认进入图片创作。
- 文生图、图生图和反推切换不丢失草稿。
- 当前生成任务不会因切换左侧模式或工作区而取消或消失。
- 单图、批量、空状态、生成中、失败和重试均有明确表现。
- 顶栏不再出现模型和独立签到按钮。
- 管理台四个一级模块职责清晰，不在总览堆叠编辑表单。
- 普通用户无法访问管理员 API。
- 管理员无法查看已创建 Key 的完整明文。
- 原有生成、对话、积分、公告、打赏和用户管理能力不回退。
- 桌面目标宽度无横向溢出，手机端核心流程可用。

## 19. 非目标

- 不重做登录页的品牌首屏。
- 不更换品牌配色和字体方向。
- 不新增生图模型能力或后端生成参数。
- 不增加完整 API 调用审计日志和逐次账单查询。
- 不在本轮增加图片与对话之间的跨模态分析能力。
- 不重构与本次 UI 工作无关的服务端业务。
