# 管理端注册 IP 限制开关

## 目标

将当前由服务器环境变量控制的“同一公网 IP 只能注册一个账号”限制，纳入管理端「站点设置」统一管理，并保持当前生产状态为关闭。

## 方案

### 数据与服务

- 在 `site_settings` 增加 `registration_ip_limit_enabled` 整数开关，`0` 表示关闭、`1` 表示开启。
- 数据库迁移使用默认值 `0`，确保迁移和部署过程中不会意外重新开启限制。
- 站点设置服务在 GET 返回布尔值，并提供管理员专用更新函数。
- 管理员 `PUT /api/admin/site-settings` 接受 `registrationIpLimitEnabled`，沿用现有管理员鉴权和错误处理。
- 注册接口从数据库读取该设置；设置关闭时跳过 `registration_records` 的 IP 检查和写入，其他注册校验保持不变。
- 删除生产 systemd 中仅用于临时控制的 `REGISTRATION_IP_LIMIT_ENABLED=false`，避免环境变量和管理端状态冲突。

### 管理端界面

- 在现有「站点设置」卡片的注册设置区域增加“同 IP 注册限制”状态按钮。
- 开启显示“限制中”，关闭显示“已关闭”，说明文字明确其只限制同一公网 IP 的重复注册。
- 保存请求使用现有 `/api/admin/site-settings` 接口；保存期间复用现有 loading 状态，成功和失败提示复用现有消息区域。
- 视觉上沿用当前管理端深色卡片、状态圆点和琥珀/危险色按钮，不引入新的交互模式。

## 安全与兼容性

- 只有活动管理员可以读取或修改该设置。
- 用户名唯一性、密码强度、邀请码校验、每小时 10 次注册限流和 Cloudflare-only 回源不变。
- 现有 `registration_records` 数据保留，不删除；开启后继续复用已有记录。
- 迁移失败时保留旧版本和旧环境变量配置，服务不切换；成功部署后可通过管理端关闭或开启。

## 测试与验证

- 增加迁移/schema 合同测试，确认字段、默认值和迁移账本一致。
- 增加站点设置服务/接口合同测试，覆盖读取、开启和关闭。
- 增加管理端设置卡片测试，确认开关文案、请求字段和状态更新。
- 增加注册策略测试，确认关闭时不执行单 IP 限制，开启时仍执行。
- 部署后验证数据库迁移、管理员设置保存、注册行为、服务状态、公共页面 200、未授权模型接口 401，以及直连源站 403。

## 回滚

保留旧生产 release；若新版本异常，将 `/opt/deeproast-current` 切回旧 release 并重启服务。数据库新增字段保留不会影响旧代码；如需恢复限制，可在管理端开启，或在回滚前暂时保留旧环境变量配置。
