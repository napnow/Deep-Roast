# 手机端键盘与底部操作区 App 化设计

## 目标

仅调整小于 768px 的生图工作台布局，使输入键盘弹出时页面不跳动、输入区紧贴键盘，且底部导航不会与输入区重叠。桌面端 UI 和现有生图、图生图、反推等业务行为保持不变。

## 根因

`ImageMobileBar` 是脱离布局的固定层；底部导航仍在普通文档流内。输入框聚焦时又调用 `lockPageScroll`，将 `body` 固定在 `top: 0`，导致 iOS Safari 打开键盘后丢失原滚动位置。外壳使用 `100svh`，无法代表键盘打开后的动态可视区域，进一步造成输入区、导航和画布的位置失配。

## 方案

采用 App Shell 模式：

1. 手机端工作台固定在动态可视高度内，页面本身不再作为滚动容器；只有结果画布可纵向滚动，并保留 iOS 惯性滚动与边界控制。
2. 通过 `visualViewport` 计算键盘占用高度和键盘打开状态。键盘打开时，生图输入区以键盘顶部为基准定位，底部导航隐藏；键盘收起时，输入区回到导航上方，导航恢复。
3. 移除文本输入聚焦时的全页滚动锁。底部设置面板继续使用现有的遮罩锁定，避免背景滚动。
4. 输入区高度变化继续同步给画布，保证结果内容永不被固定输入区遮挡。

## 组件边界

- 新的移动视口状态只负责键盘高度与打开状态，不承载业务状态。
- `ImageMobileBar` 仅消费键盘高度，不再控制整个页面的滚动锁。
- `MobileWorkspaceNav` 仅根据键盘状态显示或隐藏。
- `ImageGenView` 负责将输入区高度传递给结果画布的安全底部留白。

## 验收标准

- iPhone Safari 点击提示词输入框：当前结果位置不跳至顶部，输入区紧贴键盘上沿。
- 键盘打开时不显示底部“生图/对话/作品/我的”导航；收起后恢复。
- 结果画布可独立顺滑滚动，不会带动整页，也不会被输入区或导航遮住。
- 桌面端工作台的头部、三栏和输入区样式不变化。
- 图生图与反推的抽屉/输入操作仍可用。

## 验证

- 增加针对移动键盘状态、导航可见性和输入区定位的静态/单元契约测试。
- 运行 TypeScript 检查和相关现有移动端测试。
- 在实际 iPhone Safari 上复测键盘打开、收起和结果区滚动。
