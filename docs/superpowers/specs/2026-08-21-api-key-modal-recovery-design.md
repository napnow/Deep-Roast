# API Key 弹窗与可恢复密钥设计

## 目标

优化用户端“API 接入”弹窗的布局与操作层级，并让本次更新后创建的 API Key 在刷新页面后仍可由所属用户显示和复制。旧 Key 因系统只保存 SHA-256 哈希，无法恢复原文，允许用户主动重新生成。

## 范围

- 调整用户端 API Key 弹窗，不重做管理端界面。
- 保留现有创建、Bearer 鉴权、状态管理、使用统计和删除能力。
- 新增所属用户按需读取完整 Key、复制 Key、复制调用示例和旧 Key 重新生成能力。
- 管理员不能读取用户完整 Key；管理员现有创建、停用和删除权限不变。

## 界面设计

弹窗在桌面端采用约 36rem 的宽度，移动端保持视口内自适应。内容分为三个清晰区域：

1. 顶部标题区：图标、标题、用途与计费说明、关闭按钮。
2. Key 管理区：独立的创建表单与 Key 列表。每条 Key 展示备注、前缀、状态和最近使用时间。
3. 快速调用区：完整换行的代码块、复制示例按钮和模型查询提示，避免横向内容被裁切。

可恢复的新 Key 默认以掩码显示，提供“显示”“复制”“删除”。复制不要求先显示。旧 Key 显示“旧版 Key，无法恢复”，提供“重新生成”和“删除”。重新生成必须二次确认，并明确旧 Key 会立即失效。

创建成功后，新 Key 直接进入列表并高亮，同时出现一次轻量成功提示；弹窗不切换成阻塞式的单独成功页面。

## 数据与加密

`api_keys` 表新增可为空的密文字段、初始化向量字段和认证标签字段。旧记录的这些字段为空，因此可继续正常鉴权，但不能恢复原文。

新建 Key 时：

1. 生成随机明文 Key。
2. 计算 SHA-256 哈希，继续用于 Bearer 鉴权。
3. 使用服务器专用环境变量提供的 256 位密钥，通过 AES-256-GCM 加密明文。
4. 在同一数据库事务中保存哈希、前缀、密文、初始化向量和认证标签。

加密密钥使用独立环境变量，不从登录或会话密钥派生。部署时生成并加入服务器环境配置，必须随服务器配置备份，不写入代码库或日志。

## 接口与权限

- Key 列表接口只返回元数据和 `recoverable` 标识，不返回完整 Key。
- 新增所属用户读取单个 Key 明文的接口。接口必须校验登录态和记录所有权，然后按需解密。
- 新增旧 Key 重新生成接口。它在事务中删除旧 Key 并创建同名新 Key，避免出现两个同时有效的替代 Key。
- 读取或重新生成其他用户的 Key 统一返回“Key 不存在”，不泄露记录是否存在。
- 明文 Key 不写日志、不进入错误信息，也不提供给管理端接口。

## 兼容与失败处理

- 旧 Key 在迁移后继续有效，用户可自行决定何时重新生成。
- 解密配置缺失或密文校验失败时，接口返回通用错误，界面提示“暂时无法读取，请重新生成或联系管理员”，不回传内部加密细节。
- 重新生成失败时保留旧 Key，只有事务完全成功后旧 Key 才失效。
- 浏览器剪贴板不可用时沿用现有兼容复制方式。

## 测试与验收

测试先于实现编写，至少覆盖：

- 新 Key 加密后可正确解密，数据库中不出现明文。
- 创建后可复制，关闭并重新打开弹窗后仍可复制。
- 列表接口不返回完整 Key。
- 用户不能读取或重新生成他人的 Key。
- 旧 Key 仍可鉴权，且被标记为不可恢复。
- 旧 Key 重新生成后原 Key 失效，新 Key 可鉴权并可再次复制。
- 加密密钥缺失、密文损坏和复制失败时的错误状态。
- 弹窗在桌面和移动宽度下无横向溢出，调用示例可完整阅读和复制。

部署顺序遵循服务器优先：在服务器当前版本上应用数据库迁移、环境配置和代码改动，完成构建与健康检查后，再将同一改动同步回本地工作区。
