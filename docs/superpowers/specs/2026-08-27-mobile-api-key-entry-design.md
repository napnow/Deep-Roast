# 手机端 API Key 创建入口设计

## 目标

让所有已登录用户都能从手机端“我的”菜单进入现有“API 接入”弹窗，创建、显示、复制、重新生成和删除自己的 API Key。

## 问题根因

项目已经具备完整的用户端 API Key 能力：后端接口、加密存储、数量限制、响应式管理弹窗和桌面端入口均已存在。手机端头部会隐藏桌面用户菜单，而底部“我的”入口打开的 `MobileDrawer` 没有 API Key 菜单项，因此用户在手机端无法发现和打开现有功能。

## 方案选择

采用“复用现有弹窗，仅补移动端入口”的方案，不新增独立页面，也不在抽屉内重复实现创建表单。

这样可以保持桌面端与手机端共享同一套创建、密钥显示、复制、重新生成、删除和错误处理逻辑，并将改动限制在移动端导航接线范围内。

## 界面与交互

在手机端“我的”抽屉的账户功能区新增一项：

- 标题：`API 接入`
- 说明：`创建、复制和管理你的 API Key`
- 图标：复用现有 `AppIcon`，不扩展图标集合
- 权限：所有已登录用户可见，与桌面端保持一致

入口与“积分与邀请”“修改密码”放在同一层级。用户点击后，抽屉先关闭，再打开现有 `ApiKeysModal`，避免两个遮罩层同时存在。

现有弹窗继续负责：

- 创建带备注的 API Key；
- 显示、隐藏和复制可恢复 Key；
- 重新生成旧版或现有 Key；
- 删除 Key；
- 展示数量上限、加载状态、成功提示和错误提示；
- 在手机视口内纵向滚动，避免横向溢出。

## 组件与数据流

1. `src/components/ImageGen/MobileDrawer.tsx` 新增 `onOpenApiKeys` 回调属性和 `api-keys` 菜单项。
2. 菜单点击处理先调用 `onClose()`，再调用 `onOpenApiKeys()`。
3. `src/app/page.tsx` 向 `MobileDrawer` 传入 `() => setApiOpen(true)`。
4. Zustand 中已有的 `apiOpen` 状态驱动 `src/components/AppModals.tsx` 渲染现有 `ApiKeysModal`。
5. 弹窗继续调用现有 `/api/user/api-keys` 系列接口；不新增 API、数据库字段或迁移。

## 失败与边界处理

- 未登录用户仍由现有认证流程拦截，不为入口增加独立鉴权分支。
- 列表加载、创建、复制、重新生成和删除失败继续由 `ApiKeysModal` 显示现有错误信息。
- Key 达到数量上限时沿用服务端 `API_KEY_QUOTA` 响应和现有界面提示。
- 快速连续点击只改变同一个 `apiOpen` 布尔状态，不创建重复弹窗实例。
- 抽屉关闭后才打开弹窗，确保焦点和遮罩层级清晰。

## 测试与验收

- 先增加失败测试，确认 `MobileDrawer` 必须包含“API 接入”、说明文案和 `onOpenApiKeys` 调用。
- 更新首页移动导航测试，确认 `page.tsx` 将 `setApiOpen(true)` 接到 `MobileDrawer`。
- 运行现有 `ApiKeysModal` 测试，确认响应式布局和完整管理能力保持不变。
- 运行相关移动端测试、完整测试、Lint 和生产构建。
- 部署后以手机视口验证：“我的” → “API 接入” → 创建 Key；同时验证桌面端入口不变。
- 验证服务器 `deeproast.service` 为 active，应用端口返回成功响应。

## 部署约束

本地工作区存在大量与本功能无关的未提交改动，实施时只修改和提交本设计涉及的文件，不覆盖或提交其他改动。服务器部署基于当前活动发布创建新发布目录，只应用本功能的最小差异，完成构建与健康检查后再原子切换 `deeproast-current`，避免把本地其他未完成功能一起部署。
