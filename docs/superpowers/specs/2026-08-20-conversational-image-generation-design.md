# 对话内助手形象生图设计

## 目标

让用户在对话中用“我想看看你”“给我看看你的样子”等自然表达触发助手形象生图，并把结果作为对话中的助手图片消息展示；生图失败、超时、断流或接口无响应时必须结束加载状态并提供重试入口。

## 范围

- 支持自然语言外观请求识别，普通聊天不触发生图。
- 使用管理员配置的助手形象提示词作为固定人设基础。
- 生图结果在当前对话中显示，并在重新打开对话后保留。
- 对失败、超时、无响应 body、非正常结束的流统一收敛为可重试错误状态。
- 保留现有独立生图工作区，不改变现有图片生成接口的使用方式。

## 方案

采用服务端意图识别与结构化图片消息：

1. 对话提交后由服务端识别外观请求，命中后使用管理员配置的人设提示词和用户原话组合生图提示词；未命中继续走现有文本流。
2. 客户端在对话中先插入临时的“正在生成”图片卡片，收到成功事件后替换为图片消息。
3. 数据库消息增加可选图片关联信息，图片生成记录继续复用现有 `image_generations`，确保对话重新加载时可恢复图片。
4. 生图流程发出开始、成功、失败事件；客户端无论哪种结束路径都清理 `streaming`/pending 状态。请求设置超时，失败卡片提供重试。

## 人设配置

在现有管理/设置配置中增加助手形象提示词。为空时使用安全的默认虚构形象描述，不使用真实人物或用户隐私信息作为默认内容。

## 验收标准

- 输入“我想看看你”可触发助手形象生图并在对话中显示图片。
- 普通聊天文本不会触发生图。
- 刷新或重新进入该对话后，已生成图片仍可见。
- API 错误、超时、断流、无 response body 时，最多在超时窗口后显示失败，不会无限转圈。
- 点击重试会复用原始用户请求，不重复插入多条用户消息。
- 现有独立生图、普通对话和 API 生图接口测试不回归。
