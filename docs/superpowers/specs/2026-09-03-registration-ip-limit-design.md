# 注册 IP 限制管理开关设计

## 背景

当前 Deep-Roast 的注册接口仍通过 `registration_records` 实现同一 IP 的注册限制，但管理面板只有“开放/关闭注册”开关，没有独立控制 IP 限制的入口。服务器环境变量 `REGISTRATION_BYPASS_IPS` 也无法在管理界面查看或配置，导致管理员无法在不改服务器配置的情况下临时放开同 IP 注册。

## 目标

在“站点与内容”的站点设置中恢复一个持久化的“同一 IP 注册限制”开关，并保持现有注册安全策略和兼容行为。

## 方案

新增 `site_settings.registration_ip_limit_enabled` 字段，数据库默认值为 `1`。管理 API 的 GET 返回 `registrationIpLimitEnabled`，PUT 接收布尔值并由现有管理员鉴权保护。管理面板在“新用户注册”附近增加独立开关和说明文字。

注册流程读取该设置：

- 开关开启时，继续执行现有 `registration_records` 查询和写入；同一 IP 的第二个账号注册会被拒绝。
- 开关关闭时，跳过注册 IP 记录的查询和写入，允许同一 IP 注册多个账号。
- 既有 `REGISTRATION_BYPASS_IPS` 白名单继续作为开启状态下的例外；开关关闭时所有 IP 都不受单 IP 注册限制。
- `REGISTER_IP_LIMIT = 10` 的注册请求频率限制保持不变，不受该开关影响。
- 关闭开关不会删除历史 `registration_records`；重新开启后，保留的历史记录继续生效。

## 数据流与边界

管理面板 → `/api/admin/site-settings` → `site_settings.registration_ip_limit_enabled` → `/api/auth/register`。只有管理员可以修改设置；注册接口仍使用服务端配置和数据库状态，不信任客户端传入的开关值。数据库迁移采用 additive 方式，旧数据库在迁移后默认保持原有“限制开启”行为。

## 错误处理与兼容

布尔值以外的 PUT 输入按现有站点设置 API 的约定忽略或拒绝，不能把字符串 `"false"` 当成开启。读取旧记录中为空的字段时按开启处理。现有白名单、注册总开关、邀请奖励和登录限流不改变。

## 测试与验收

- 增加设置解析/更新测试，覆盖默认开启、明确关闭和非法输入。
- 增加注册策略测试，覆盖开启时拒绝重复 IP、关闭时允许重复 IP、白名单例外以及注册频率限制仍存在。
- 增加管理设置 API/UI 数据字段测试，确认开关文案和 PUT 请求字段一致。
- 运行完整测试、TypeScript 检查、ESLint 和生产构建。
- 部署后验证普通用户不能修改设置，管理员切换后注册接口行为实时使用新值，现有服务和数据不受影响。

## 不在范围内

不修改 IP 获取方式、不删除历史注册记录、不移除 `REGISTRATION_BYPASS_IPS`、不改变注册频率限制、不增加按用户或按设备的其他风控策略。
