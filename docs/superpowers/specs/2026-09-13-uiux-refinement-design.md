# DeepRoast responsive workbench refinement

The user requested continuation of the already presented four V1 previews. Preserve the warm paper/caramel identity and existing billing/upload behavior. Implement the previously recommended first batch, not a wholesale redesign.

## Scope and acceptance
1. Desktop retains three columns when space permits. At 768–1199px use a compact creation column plus a usable canvas; history remains available in an on-demand drawer. Saved column widths must not squeeze the canvas.
2. A shared native-dialog foundation gives preview, confirmation, password and mobile tools top-layer stacking, Escape, focus containment/return and scroll locking. Nested confirmation closes independently.
3. Mobile and desktop share the existing session-scoped prompt, size, count and style draft. Failure does not clear input. Existing account-reset and async-cancellation guarantees remain intact.
4. Current model, count, estimated total credits and balance are visible before generation without horizontal scrolling. Model rows show a readable name, exact ID and per-image price; administrators are explicitly free.
5. Compact image-edit reference cards and secondary explanations so modification input is easy to reach. Keep advanced settings and existing lifecycle behavior.
6. Correct password labels, nested main semantics, and touched low-contrast text. No broad store/CSS rewrite, new gallery feature set or speculative caching.

## Delivery boundaries
Cover desktop, tablet and mobile browsers. Automated viewports are not physical iOS/Android validation. Keep real-user data and paid generations out of tests. Preserve previous release, local environment, master and existing stash. Build offline and use reversible single-instance delivery. Source security review limitations must be reported rather than claimed as passed.
