# DeepRoast 生产安全加固设计

## 目标

在不改变现有用户 API 地址、API Key、模型行为和生图质量的前提下，修复已确认的高风险代码与部署问题，并以可回滚方式发布到 `20.41.121.31:/opt/deeproast`。

本次成功标准是：高危漏洞得到回归测试覆盖，生产构建与类型检查通过，高危依赖告警清除，公网只能经 Cloudflare 访问 DeepRoast，现有 `/api/v1` 用户调用保持可用，照片原文件和图片数据库记录不发生清理或重写。

## 范围

### 本次包含

- 修复模型目录接口的 SSRF 与服务器上游密钥外带风险。
- 修复聊天和图生图的并发扣费绕过，保证余额和积分流水一致。
- 限制请求体、参考图、远程图片下载、提示词、聊天内容和图片尺寸所占资源。
- 校验对话使用的模型必须属于管理员启用列表。
- 对外隐藏内部异常和上游错误细节。
- 更新存在高危安全公告的 Next.js、Sharp 及相关传递依赖。
- 增加浏览器安全响应头，关闭 Next.js 技术标识响应头。
- 为会话消息、图片历史、积分流水和 API Key 常用查询增加索引。
- 采用独立发布目录，降低生产切换和回滚风险。
- 将 DeepRoast 改为专用低权限系统用户运行。
- 仅允许 Cloudflare 回源访问 DeepRoast；项目上游端口 2567 和 5661 仅本机可达。

### 本次不包含

- 不删除、归档、压缩、迁移或重新生成 `public/images`、缩略图及数据库图片记录。
- 不处理与 DeepRoast 无关的 Xray 8317 端口。
- 不引入 Redis、任务队列、对象存储或完整 CSP 改造。
- 不重构无关前端组件，也不改变现有产品交互。
- 不主动进行会消耗积分或上游额度的真实生图冒烟测试。

## 已确认兼容性约束

- 用户继续调用 `https://deeproast.sryze.cc/api/v1`，路径和认证方式不变。
- 2567 和 5661 仅本机监听后，DeepRoast 与 Caddy 仍可访问这些上游；只有直接访问 `20.41.121.31:2567` 或 `:5661` 的方式会被关闭。
- 原有 API Key 不轮换、不失效、不改变存储格式。
- 模型、提示词、上游 `quality` 参数、尺寸映射和重试策略保持不变。
- 成功生成的原图不增加压缩或降采样；现有 `gpt-image-2` 精确裁切流程保持不变。
- 缩略图仍与原图分开；下载和最终结果继续使用原图。

## 发布架构

新版本在 `/opt/deeproast/releases/<timestamp>` 中安装依赖、构建和验证。当前 `/opt/deeproast` 工作树包含用户未提交修改，因此不直接覆盖，也不清理其工作树。

发布目录继续使用现有 `/opt/deeproast/.env.production` 和数据库，并通过受控符号链接共享 `/opt/deeproast/public/images` 与 `/opt/deeproast/public/uploads`。图片写入仍落到现有数据目录。systemd 在切换窗口中把 `WorkingDirectory` 指向新发布目录；失败时恢复原单元文件和原工作目录。

切换前保存以下回滚材料：

- PostgreSQL 逻辑备份及迁移前记录计数。
- 当前 Caddyfile 和通过校验的 Caddy配置副本。
- 当前 systemd 单元文件。
- 当前应用版本、Git HEAD、工作树状态和运行参数。

## 代码设计

### 模型目录与上游地址

`GET /api/models` 继续允许已登录且状态正常的用户读取管理员已经保存的模型目录。调用者不能影响该请求使用的 Base URL 或凭证。

`POST /api/models` 改为仅管理员可用。只要请求提供自定义 Base URL，就必须同时提供本次请求的显式 API Key，绝不回退到数据库或环境变量里的服务器密钥。请求不跟随重定向，并设置 20 秒超时。自定义公网地址只接受 HTTPS；已经由管理员保存、供本机上游使用的地址可继续使用 HTTP 或回环地址。

响应和日志不得包含 API Key。上游响应正文只在服务器日志中保留截断后的脱敏摘要，不返回给客户端。

### 积分预扣与退款

积分余额变更和 `credit_transactions` 流水写入放在同一个数据库事务中。每次收费任务先进行带余额条件的原子扣减；余额不足时不调用上游。

聊天流程为：

1. 鉴权、限流并有界读取请求。
2. 校验会话归属、模型和内容。
3. 原子预扣一次聊天积分。
4. 写入用户消息并调用上游。
5. 流式转发有效内容，完整结束后保存助手消息。
6. 上游在产生任何有效内容前失败、返回空内容或请求准备阶段失败时，只执行一次幂等退款。

一旦已经向客户端转发有效内容，之后发生流中断仍保留扣费，因为上游成本已产生，也防止主动断开获取免费内容。客户端主动断开不触发退款。

图生图与批量图生图按单个输出任务独立执行：每个任务调用上游前原子预扣 5 积分，失败时清除该任务的临时文件和不完整记录，并只退款该任务。批量任务成功几张就只收几张。管理员沿用现有免扣费规则。

文生图已采用预扣与失败退款，改造时统一复用同一事务接口，防止余额与流水分离。

### 请求和资源边界

`readJson` 改为流式有界读取。普通 JSON 请求体上限为 1 MiB，图生图请求体上限为 30 MiB；超过上限返回 413，读取器立即取消剩余请求体。

图生图继续最多接受 5 张参考图。服务端不重压缩参考图，但验证 Data URL 类型、Base64 格式和解码后大小。客户端提交的远程图片只允许 HTTPS 公网地址或本站 `/images` 资源；服务器受控下载后再提交上游，禁止访问回环、私网、链路本地和云元数据地址，不跟随重定向。单个远程图片响应最大 25 MiB，并检查成功状态和图片内容类型。

图片上游请求设置最长 300 秒超时，聊天和反推请求设置合理的连接及总时限。超时统一返回 504 或公开的上游暂不可用错误。

图片尺寸必须是正整数 `宽x高`。单边不超过 2048 像素，总像素不超过 4,194,304；这覆盖现有 UI 最大 1920 像素的选项。超限时直接拒绝，不自动缩放、不改变质量。非裁切模型继续遵循其支持尺寸集合。

提示词最长 2,000 个字符；聊天单条用户内容最长 20,000 个字符。对话模型必须出现在管理员启用的文本模型列表中。

### 文件一致性

上游返回的原图在边界检查后按原始字节写入，现有必要裁切除外。落盘、缩略图和数据库写入任何一步失败时，删除本次新建的临时文件或记录；绝不扫描、修改或清理历史图片。

使用临时文件和原子重命名避免客户端看到半写文件。缩略图失败继续不影响原图成功结果，行为与当前系统一致。

### 错误和日志

已知 `ApiError` 保留经过审查的公开消息和状态码。未知异常只返回固定的“服务器错误”；上游异常返回稳定的 502/504 文案，不返回上游正文、内部路径、SQL、堆栈或主机详情。

日志记录请求编号、用户 ID、接口、上游主机、状态码、耗时、重试次数和退款结果。日志禁止记录 API Key、Authorization、Cookie、会话令牌和 Base64 图片正文。

### 依赖和响应头

Next.js 升级到已修复当前安全公告且与现有 16.x 代码兼容的补丁版本，`eslint-config-next` 保持同版本。Sharp 升级到 0.35.3 或更高兼容补丁；NanoID、PostCSS 等传递依赖解析到无当前高危公告的版本。依赖更新后锁定 `package-lock.json`。

Next.js 关闭 `X-Powered-By`。Caddy 为 DeepRoast 添加 HSTS、`X-Content-Type-Options: nosniff`、严格 Referrer Policy、Permissions Policy 和点击劫持保护。严格 CSP 不在本次启用，避免未经完整页面测试破坏 Next.js 内联资源。

### 数据库索引

新增以下面向现有查询模式的索引，均不改变数据内容：

- `conversations(user_id, updated_at)`
- `messages(conversation_id, created_at)`
- `image_generations(user_id, created_at)`
- `credit_transactions(user_id, created_at)`
- `api_keys(user_id, status)`

迁移前备份数据库并记录主要表计数，迁移后再次核对。当前数据量较小，可使用普通 `CREATE INDEX IF NOT EXISTS`，预计锁定时间短；若现场数据库状态与迁移日志不一致，则停止迁移并先修正计划，不猜测执行。

## 基础设施设计

### Cloudflare 与 Caddy

DeepRoast 域名只接受来自 Cloudflare 官方 IPv4/IPv6 地址段的连接。Cloudflare 地址段在变更当天从官方来源获取、保存并校验，禁止使用未经验证的第三方列表。

Caddy 配置受信代理链，移除客户端自带的 `CF-Connecting-IP`、`X-Forwarded-For` 和 `X-Real-IP`，再把经过可信代理解析的客户端地址传给 Next.js。这样应用限流使用的来源地址不可由公网客户端伪造。

配置先运行 `caddy validate`，再执行无中断 reload。验证经 Cloudflare 域名访问正常，并使用直接源站解析测试确认返回拒绝。

### 上游端口

2567 与 5661 改为仅绑定 `127.0.0.1`，并在主机防火墙增加兜底拒绝规则。Caddy 和 DeepRoast 仍从本机访问它们。对公网探测应不可连接，而 `/api/v1` 经 Cloudflare 继续正常。

Xray 8317 不属于本项目，本次不修改。

### systemd 权限

创建无登录 shell 的 `deeproast` 系统用户和组。发布代码只读，只有共享图片、上传和必要运行缓存目录赋予写权限。环境文件继续由 root 管理，不改变密钥内容。

服务单元使用 `User=deeproast`、`Group=deeproast`、`NoNewPrivileges=true` 和 `PrivateTmp=true`。暂不启用可能影响 Next.js 运行缓存的激进文件系统隔离。保留现有内存限制，确认新边界下运行稳定后再单独评估。

## 测试策略

所有代码修复遵循红—绿—重构：先写能复现漏洞或竞态的失败测试，确认失败原因正确，再写最小修复并运行完整回归。

至少覆盖：

- 非管理员不能提交自定义模型目录请求。
- 自定义 Base URL 不会获得数据库或环境变量密钥。
- 自定义 URL 重定向、私网/元数据访问和超时策略。
- 同一余额下并发聊天、单图和批量图生图不能超额使用。
- 上游调用前失败、空响应和图生图最终失败只退款一次。
- 成功图片原始字节、模型、尺寸和质量参数保持不变。
- 普通和图生图请求体边界、非法 Base64、超大图片和危险尺寸。
- 任意未启用文本模型被拒绝。
- 未知异常和上游正文不会泄露给客户端。
- 新数据库索引存在且主要表迁移前后记录数相同。

发布门槛：

- 全量 `npm test` 通过。
- `tsc --noEmit --incremental false` 通过。
- 生产 `npm run build` 通过。
- 本次修改文件无新增 ESLint 错误；现有无关 lint 基线单独记录，不用放宽规则掩盖。
- `npm audit --omit=dev` 无高危漏洞。
- `caddy validate` 和 `systemd-analyze verify` 通过。

## 发布、冒烟与回滚

发布前在独立目录安装锁定依赖并构建。准备完成后进入一次短切换窗口：备份配置和数据库、执行索引迁移、切换 systemd 工作目录和运行用户、重载 Caddy、收紧上游端口，然后启动新服务。

冒烟测试包括：

- 首页、登录页和只读公开接口正常。
- 未认证 `/api/v1` 请求正确返回 401。
- 使用现有有效 API Key 在不消耗积分的 `/api/v1/models` 验证认证链路，命令不得输出密钥。
- Cloudflare 域名访问正常，直接源站访问被拒绝。
- 2567 和 5661 公网不可连接，本机健康检查正常。
- systemd 无重启循环，日志无新增密钥或内部错误泄露。

上线后至少观察 10 分钟的 5xx、上游错误、内存峰值和 systemd 状态。任一关键冒烟失败、持续 5xx、服务重启循环、数据库计数异常或 `/api/v1` 认证失败都触发回滚：恢复原 systemd/Caddy/端口配置，切回 `/opt/deeproast`，必要时恢复数据库备份，并保留新发布目录用于离线诊断。

## 验收条件

- 现有网页和 `https://deeproast.sryze.cc/api/v1` 可用，现有 API Key 无需更换。
- 直接源站访问被拒绝，来源 IP 不能由客户端伪造。
- 2567 和 5661 不再公网开放，8317 未改变。
- 已确认的 SSRF、密钥外带、并发扣费绕过、资源耗尽和错误泄露均有通过的回归测试。
- 成功生图的模型、请求尺寸、质量参数和原图存储行为未发生降质变化。
- 高危生产依赖告警清除，生产构建通过。
- 数据库记录计数保持一致，仅增加计划内索引。
- 历史照片、缩略图及其数据库记录未被清理或重写。
- 新版本稳定观察至少 10 分钟，且保留可执行回滚路径。
