# 生成图片继续修改

## 目标

让用户无需下载图片再上传，也能把任意已生成图片直接作为图生图目标图继续修改。

## 范围

- 生成完成后的结果画布：提供显眼的“继续修改”按钮。
- 历史图库与大图预览：提供同一操作，但作为次级操作，避免缩略图界面拥挤。
- 点击后进入既有图生图模式，带入图片 URL、原提示词和原画幅比例。

不新增接口、文件上传、图片副本、积分规则或模型配置。

## 交互与数据流

1. 用户在结果画布、图库详情或预览中选择“继续修改”。
2. 前端写入既有 `imageToImageDraft`：目标图为当前 `ImageRecord.imageUrl`，提示词和尺寸沿用该记录。
3. 前端切换到既有 `imageCreationMode = "edit"`；手机端同时打开图生图编辑面板。
4. 用户改写提示词后按现有图生图流程提交。图片仍通过既有 `/api/image-edit` 或批量编辑流程处理。

## 组件边界

- 新增一个轻量的“继续修改”回调，由 `ImageGenView` 集中把图片记录转换为既有草稿状态。
- `ResultCanvas`、图库详情/预览只负责触发回调，不直接写全局 store。
- 已存在的桌面资源详情“进入图生图”与新回调收敛到同一入口，保证桌面、手机和历史图片行为一致。

## 异常与兼容

- 缺少图片 URL 时禁用入口并不切换模式。
- 不改变下载、复制提示词、删除或图片预览的现有行为。
- 沿用图生图本身的图片数量、余额和上游错误提示。

## 验证

- 单元/静态交互测试覆盖：结果画布与历史/预览均暴露继续修改入口；回调带入 URL、提示词、尺寸并切换 `edit` 模式。
- 现有图生图移动流程测试继续通过。
- TypeScript 与生产构建通过。
