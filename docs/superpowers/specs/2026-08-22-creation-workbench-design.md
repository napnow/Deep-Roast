# 深焙创作控制台设计规格

**日期：** 2026-08-22  
**状态：** 已确认视觉方向，待实施  
**范围：** 桌面创作控制台、移动端创作抽屉、对话/创作/图库入口关系

## 目标

将现有“参数堆叠式”图像生成面板改造成一个清晰的创作工作台：用户能够快速选择创作模式、管理参考图、理解多图编辑关系、填写一条主要指令并提交任务，同时保留现有对话功能和图像生成后端能力。

## 当前问题

1. 模式、素材、修改方式、提示词、风格、比例和数量在同一条纵向流中竞争注意力。
2. 多图分别修改时，每张图片都显示一个窄小输入框，图片与指令的对应关系不够明确。
3. 普通区域、选中区域和主要操作都使用相似的圆角卡片，视觉层级不足。
4. 生成操作和积分状态不够稳定地出现在用户视线内。
5. 桌面端 `CreationPanel`、移动端 `ImageMobileBar` 与旧的 `ImageInputColumn` 存在相似交互，容易产生模式和文案不一致。
6. 当前视觉稿只展示了创作控制台局部；对话功能必须作为一级能力保留，不能被创作工作台替代。

## 设计原则

- 先让用户理解“我正在编辑什么”，再让用户调整参数。
- 一次只突出一个主要指令输入框。
- 参考图是任务素材，不是装饰缩略图；目标图和参考图必须有明确身份。
- 默认只展示完成一次生成所必需的控件，高级选项按需展开。
- 桌面端和移动端使用同一套任务状态与编辑语义，只改变布局和呈现方式。
- 保留现有米白、深咖啡和陶土色品牌气质，减少无意义的容器和嵌套圆角。

## 信息架构

### 一级应用入口

对话、创作、图库是并列的一级入口；公告等辅助能力继续放在现有导航体系中。

- 桌面端：通过现有应用导航进入 `ChatView`、创作工作台和图库。
- 移动端：通过底部导航切换“对话 / 创作 / 图库”。
- 对话中触发图像任务时，继续使用现有任务状态，并允许跳转到创作工作台查看或继续编辑。
- 创作工作台不是替代对话页的全屏壳层；它是独立的图像任务工作区。

### 桌面端三栏

桌面端保持三栏结构，但重新分配视觉权重：

1. 左侧创作工作区，宽度约 340–380px。
   - 顶部：创作标题、文生图/图生图/反推模式切换。
   - 主体：素材轨道、编辑方式、当前编辑对象、单一主指令、高级设置。
   - 底部：固定生成操作栏，显示生成数量、预计积分和停止状态。
2. 中央结果画布，占据剩余主要空间。
   - 空状态保持简洁的虚线画布和“创作舞台已就绪”。
   - 有结果时展示结果网格和预览操作，不被左侧参数卡片抢占视觉重点。
3. 右侧素材库/检查器，宽度约 260–300px。
   - 搜索、筛选、缩略图网格和当前选中素材详情保持紧凑。
   - 右侧支持折叠，折叠后不影响中央画布。

### 移动端

移动端默认只展示结果画布和底部输入工具栏：

- 工具栏提供图生图、反推、比例和主输入入口。
- 点击图生图后，从底部打开带拖拽手柄的抽屉，而不是把完整表单直接插入页面流。
- 抽屉高度约为视口的 65–80%，内部独立滚动，底部操作按钮固定在抽屉内。
- 抽屉内依次展示：参考图横向轨道、编辑方式、当前编辑对象、主指令、更多设置。
- 键盘弹出时，抽屉和输入框使用 visual viewport 与安全区信息，避免工具栏被键盘或 iPhone 手势区遮挡。
- 图库和对话继续通过移动端一级导航访问，不与图生图抽屉混在同一滚动层中。

## 图生图交互

### 素材轨道

- 参考图最多 5 张。
- 每张素材显示连续编号、删除操作和选中态。
- 添加参考图使用一个固定的“+ 添加参考图”卡片，不再让按钮和缩略图挤在同一行。
- 素材轨道在移动端水平滚动，在桌面端允许换行但保持统一缩略图尺寸。

### 分别修改

- 用户选择“分别修改”后，任务仍然覆盖全部已上传图片。
- 只有一个“当前编辑：图片 N”选择器和一条主指令输入框。
- 切换当前图片不会丢失其他图片的指令；每张图片的内容保存在现有 `perImagePrompts` 状态中。
- 图片没有单独指令时，提交时继续使用公共修改要求作为回退。

### 参考修改

- 用户选择一张目标图，再选择一张或多张参考图。
- 目标图不能同时出现在参考图集合中。
- UI 必须用“目标图”和“参考图”两个明确标签表达关系，不依赖用户猜测缩略图顺序。
- 提交仍使用现有 `ImageEditRequest` 的 `reference` 语义，不改变服务端协议。

### 指令与风格

- 图生图只保留一条主要修改指令，placeholder 使用“描述你想要的修改…”。
- 风格预设进入“更多设置”，选中后在折叠行摘要中显示。
- 风格前缀仍由现有 `compileEditPrompt` 生成，UI 只改变编辑方式，不改变提示词编译规则。

### 生成状态

- 未上传图片：生成按钮禁用，并提示需要添加参考图。
- 正在生成：主按钮切换为“停止生成”，保留经过时间和处理中状态。
- 请求失败：错误信息出现在主指令区域下方，不把布局整体推得过长。
- 生成完成：保持现有任务结果刷新和面板清理行为。
- 费用和余额信息在生成按钮附近稳定显示；管理员状态继续显示免费文案。

## 文生图与反推

- 文生图沿用同一套“主指令 + 更多设置 + 固定操作栏”结构。
- 风格、比例和数量作为设置项，不再全部以大卡片展开。
- 反推保持现有上传、分析和带入文生图流程，只使用相同的素材区和状态反馈样式。
- 三种模式切换只切换任务内容，不改变桌面三栏骨架和移动端底部工具栏位置。

## 视觉系统

### 色彩

- 页面背景：暖象牙白 `#F5F2EA`。
- 内容面：浅米色/纸张色 `#E8E2D6`。
- 主文字：深咖啡 `#2C2925`。
- 次要文字：灰褐色 `#77736B`。
- 强调色：陶土棕 `#A95A32`。
- 陶土色只用于当前模式、选中素材、焦点、主要生成按钮和重要状态。

### 容器和间距

- 页面只使用背景、内容面和选中面三种主要层级。
- 普通容器使用 1px 边框和 10–14px 圆角；避免连续嵌套大圆角。
- 章节之间使用 16–20px 间距，字段内部使用 8–12px 间距。
- 触控目标不小于 44px；桌面按钮不小于 36px。
- 阴影仅用于移动端抽屉、固定操作栏和弹层，普通字段不使用重阴影。

## 组件边界

优先在现有组件边界内完成重构，避免同时改动服务端：

- `src/components/ImageGen/CreationPanel.tsx`：桌面端主工作台骨架、模式与固定操作栏。
- `src/components/ImageGen/Img2ImgPanel.tsx`：图生图素材轨道、编辑关系和单一主指令。
- `src/components/ImageGen/TextToImageForm.tsx`：文生图主指令与折叠设置。
- `src/components/ImageGen/ImageMobileBar.tsx`：移动端底部工具栏和图生图抽屉。
- `src/components/ImageGen/ImageGenView.tsx`：对话/创作/图库容器关系和响应式入口协调。
- `src/components/ImageGen/ResultCanvas.tsx`、`AssetInspector.tsx`：仅做视觉令牌和布局对齐，不改变结果和图库业务逻辑。
- `src/app/globals.css`：统一创作工作台的布局、间距、颜色和抽屉样式。

## 非目标

- 不修改多图编辑 API、代理协议或 `ImageEditRequest` 数据结构。
- 不删除或替换现有 `ChatView` 对话功能。
- 不重新设计管理员页面、登录页面或普通聊天消息气泡。
- 不引入新的 UI 框架或大型依赖。
- 不把效果图中的示例图片作为项目资源提交。

## 验收标准

1. 桌面端可以明确识别“左侧配置 / 中央结果 / 右侧素材库”三栏职责。
2. 图生图默认状态下不同时显示多条窄小图片指令输入框。
3. 分别修改和参考修改都能通过清晰的目标/参考关系完成现有结构化任务提交。
4. 生成按钮、积分/免费状态和停止生成状态在桌面端固定可见，在移动端抽屉内固定可见。
5. 移动端键盘弹出时，输入框和生成操作不被遮挡，抽屉不会产生双重滚动条。
6. 对话、创作和图库入口仍然可访问，创作工作台不会覆盖或删除对话功能。
7. 现有图生图、文生图、反推相关测试继续通过，TypeScript、lint 和 build 通过。
8. 桌面和移动端都使用同一套品牌色和选中态规则，不出现旧版与新版控件混用。
