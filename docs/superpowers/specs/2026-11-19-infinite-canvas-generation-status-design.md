# 无限画布生成等待状态设计

## 背景

单图模式已经有统一的生成等待组件：`ThinkingOrb`、已耗时读秒、三阶段提示（解析画面、渲染构图、收尾细节）和停止操作。无限画布目前只有一个全局文字提示，无法让用户知道哪个节点正在生成、哪些节点排队，也无法在多个节点同时生成时分别停止或重试。

项目服务端的图片并发限制为 2。无限画布在客户端增加同样的画布级并发上限，同时保留服务端限制作为最终保护。

## 目标

- 支持多个画布节点提交生成任务。
- 画布内最多同时运行 2 个节点，其余任务排队。
- 每个节点显示自己的等待阶段、耗时、停止、完成和失败状态。
- 生成过程中画布仍可拖动、缩放、编辑其他节点。
- 复用单图生成的阶段指示和视觉语言，避免两套等待体验不一致。
- 生成结果继续沿用现有节点连接、作品库写入和版本关系。

## 不在范围内

- 修改服务端图片并发上限。
- 持久化“正在生成”状态；刷新页面后只恢复已保存的节点和作品。
- 为等待态增加真实百分比进度。上游没有可用的百分比进度时，只显示已耗时和阶段估计。
- 重做无限画布整体工具栏或节点视觉风格。
- 让服务端返回真实的百分比或剩余时间；当前只能显示阶段估计和已耗时。

## 用户界面

### 节点状态

每个生成任务以 `nodeId` 作为稳定标识；同一节点在已有任务未结束前不能重复提交。状态包括：

- `queued`：排队中，显示排队位置或“前面还有 N 个任务”。
- `generating`：复用 `ThinkingOrb`、三阶段 `ImageGenStageIndicator`、已耗时读秒和停止按钮。
- `success`：节点替换为生成结果，保留原有连线，短暂显示“已生成”。
- `error`：节点显示失败原因、重新生成和删除节点操作。
- `cancelled`：排队任务直接移除；运行中任务停止后保留原节点内容并显示“已取消”。

空节点的等待态使用完整等待卡。已有图片的修改使用原图暗化背景和轻量等待层，保留用户对原图的空间定位。提交后自动收起提示词编辑面板；用户仍可操作其他节点，生成节点上的状态层提供停止和重试入口。

### 画布队列汇总

画布底部显示一个紧凑的汇总条，例如“正在生成 2 个 · 排队 1 个”。点击后展开任务列表。列表显示节点提示词摘要、状态、耗时和对应操作，不能遮挡画布主操作区。

全局汇总只负责概览，详细状态始终以节点为准。多个节点完成时不自动打开大图预览，避免打断画布工作流。

### 状态文案

继续使用现有阶段文案和 `formatTime` 读秒。等待态不承诺完成时间，不使用虚假的百分比。批量结果显示成功和失败数量，例如“已生成 2 张，另有 1 张失败”。

## 状态与数据流

新增画布内生成任务状态表和队列控制器：

```ts
type CanvasGenerationTask = {
  taskId: string;
  nodeId: string;
  status: "queued" | "generating" | "success" | "error" | "cancelled";
  queuedAt: number;
  startedAt?: number;
  elapsedSeconds: number;
  count: number;
  completed: number;
  failed: number;
  error?: string;
};
```

- 提交节点时先写入 `queued`。
- 调度器最多启动 2 个任务；任务完成、失败或取消后启动下一个排队任务。
- 调度器放在 `InfiniteImageCanvas` 及其专用 hook 中，页面只负责执行实际 API 调用并回传结果。
- `onGenerate` 改为接收 `{ signal }` 或等价的请求上下文；`apiJson`、批量变体请求和变体并行 helper 都要传递该 `AbortSignal`。
- 每个运行任务拥有独立的 `AbortController`，停止只影响对应节点；排队任务取消时不创建请求。
- 生成回调仍返回生成图片 ID，由现有逻辑负责插入作品库、加入画布和建立连接。
- 任务状态是内存态，不写入画布布局接口；布局只保存节点、连线和视口。
- 页面卸载时取消本地控制器，未完成任务不伪装成成功。
- 计时器只更新任务状态和对应节点的轻量数据，不通过每秒重建全部 `nodes` 数组更新 React Flow，避免拖动中的节点跳动或位置丢失。
- 节点被删除时取消其任务并忽略迟到的结果；已经由服务端保存的作品仍保留在作品库中，不自动删除。

画布级队列是用户体验层的限制；服务端的 `imageConcurrency` 仍是最终并发保护，因此单图页面和画布同时使用时，服务端仍可排队。

## 错误处理

- 排队任务取消：不发请求，不扣积分。
- 运行任务停止：中止对应请求；若上游已经完成但响应尚未到达，沿用现有幂等和成功结果处理规则。
- 如果请求已产生服务端结果但客户端在响应前取消，不能重复提交；依靠现有幂等键和迟到结果保护处理。
- 网络、积分或服务错误只更新对应节点；其他任务继续运行。
- 部分成功保留成功结果，失败数量和最后错误显示在对应节点与汇总条中。
- 页面刷新不恢复进行中的请求，只恢复已经保存的作品和画布布局。

## 可访问性与交互

- 节点等待状态使用 `role="status"` 和 `aria-live="polite"`，错误状态使用明确的错误提示。
- 停止、取消、重试按钮使用真实按钮和可访问名称。
- 队列汇总条可通过键盘展开，任务列表中的操作保持焦点可达。
- 画布拖动、缩放和节点操作在等待状态下继续可用。

## 验证范围

1. 一个节点生成：阶段、读秒、停止、成功结果与单图一致。
2. 三个节点同时提交：两个运行、一个排队；前一个完成后第三个自动启动。
3. 分别取消排队任务和运行任务，确认其他任务不受影响。
4. 两个任务一成功一失败，确认成功结果保留且失败节点可重试。
5. 图生图批量结果显示成功/失败数量，并正确连接到来源节点；单个任务内部的多张变体不伪造逐张实时进度。
6. 生成期间拖动画布、缩放、编辑文本节点不丢失任务状态。
7. 页面刷新或离开后不出现虚假的“生成中”，已完成布局和作品仍可恢复。
8. 删除正在生成的节点后，迟到结果不会重新创建画布节点。
9. 运行现有类型检查、Lint、单元测试、UIUX 回归和无限画布 smoke 测试。
