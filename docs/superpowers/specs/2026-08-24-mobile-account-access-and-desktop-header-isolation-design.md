# 手机账户入口与桌面头部隔离设计

## 目标

补齐手机端侧边栏的账户入口，同时保证电脑端只显示原有桌面头部，不增加或替换任何桌面端功能与布局。

## 范围与约束

- 不新增 API、数据库字段、页面路由或账户业务逻辑。
- 手机端侧栏复用已有钱包、邀请、修改密码和打赏弹窗。
- 积分与邀请合并为一个入口：现有钱包弹窗已展示余额、积分流水、邀请链接与邀请记录。
- 打赏入口只在现有 `donationEnabled` 为真时显示。
- 电脑端保持既有菜单、品牌、工作区切换、公告、打赏、积分和用户菜单；手机头部在 `48rem` 及以上宽度必须不可见。
- 所有手机专用界面仍限于小于 `48rem` 的断点。

## 现有能力与数据流

`src/app/page.tsx` 已持有 `donationEnabled`、`donationOpen`，并通过 Zustand store 暴露 `setWalletOpen` 与 `setPwOpen`。

`src/components/AppModals.tsx` 已渲染：

- `CreditWalletModal`：余额、积分流水、邀请链接、邀请记录和内嵌打赏。
- `ChangePasswordModal`：修改密码。
- `DonationModal`：打赏。

因此 `MobileDrawer` 只接收三个回调：打开钱包、打开改密弹窗、打开打赏弹窗；点击后先关闭抽屉，再调用回调。

## 侧边栏信息架构

在签到卡片下方，按以下顺序显示：

1. 积分与邀请：副文案显示“查看余额、积分明细和邀请链接”，打开钱包。
2. 修改密码：副文案显示“更新登录密码”，打开修改密码弹窗。
3. 打赏支持：仅在启用时显示，副文案显示“支持深焙持续运营”，打开打赏弹窗。
4. 会话记录与公告：保持现有行为。
5. 深色模式：保持现有行为。

入口使用现有 `AppIcon` 图标，不增加图标集合；抽屉滚动区域保持可滚动，底部主题开关保持固定。

## 桌面头部隔离

`Header` 同时包含手机与桌面头部，视觉隔离依赖 Tailwind 的 `md` 工具（`48rem`）。自定义 CSS 也统一使用该阈值：

- 默认 `.mobile-app-header { display: none; }`。
- 仅 `@media (max-width: 47.999rem)` 将其设为 `grid`。
- `@media (min-width: 48rem)` 再以 `display: none !important` 作为防御，防止旧 CSS 顺序或浏览器缓存造成双层头部。

桌面头部仍由现有 `hidden md:flex` 控制，不修改其内部结构或样式。

## 测试与验收

- 静态组件测试确认抽屉存在三项账户入口，且钱包、改密、打赏回调均被传入并触发。
- 静态样式测试确认手机头部仅在小于 `48rem` 显示，且在 `48rem` 及以上被显式隐藏。
- 执行既有手机图生图与创作面板测试，确保没有改变业务流程。
- 本地生产构建通过后部署；服务器生产构建、服务状态和首页响应均正常。
- 部署后以手机宽度与桌面宽度分别截图验证：手机能打开上述三个入口，电脑端仅保留一层原头部。
