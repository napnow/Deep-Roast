# 公告通知铃铛入口设计

## 目标

把公告从不明显的用户菜单入口，改为工作台顶栏中积分按钮左侧的独立通知入口；登录页不再请求或展示公告内容。

## 用户体验

- 工作台顶栏显示一个可访问的通知铃铛按钮，位置固定在积分按钮左侧。
- 有未读公告时显示红色数字角标：1–9 显示实际数量，超过 9 条显示 `9+`；没有未读公告时不显示角标。
- 新公告入口使用轻量的铃铛/角标反馈动效，遵守 `prefers-reduced-motion`，不播放声音。
- 点击铃铛打开现有公告浮层，浮层继续复用现有公告列表、加载态和空态；打开后将当前公告标记为已读。
- 浮层支持关闭按钮、点击外部关闭和键盘焦点可见状态，并在窄屏下不超出视口。
- 用户菜单中移除“公告”菜单项和其独立公告浮层，避免同一功能出现两个入口。
- 手机端现有“公告”Tab 保留，作为完整公告列表入口；铃铛是工作台顶栏的主要提醒入口。
- 登录页移除公告 API 请求、公告状态和公告渲染块；登录/注册流程及其他登录页内容不受影响。

## 组件与数据流

### `AnnouncementBell`

新增 `src/components/Header/AnnouncementBell.tsx`，负责通知按钮、未读角标、浮层开关和外部点击关闭。

- 使用现有 `useAnnouncements` 获取列表、加载状态和已读操作。
- 首次挂载后加载 `/api/announcements`，不新增 API。
- 从公告列表和已读记录推导未读数量；`useAnnouncements` 对外提供 `unreadCount`，同时保留现有 `unread` 兼容调用方。
- 公告浮层继续使用 `AnnouncementList`，不复制公告展示逻辑。
- 不引入 `framer-motion` 等新依赖；动效使用现有 CSS/Tailwind 能力。

### `Header`

在现有右侧操作组中按以下顺序渲染：`AnnouncementBell` → 积分按钮 → `UserMenu`。通知入口独立于钱包和用户菜单，保持积分按钮原有点击行为与低积分样式。

### `UserMenu`

删除公告相关状态、`useAnnouncements` 调用、公告加载副作用、公告菜单项和公告浮层；保留账户、站点主题、管理员和退出登录菜单功能。

### `LoginPage`

删除 `Announcement` 类型导入、公告 state、公告 API 请求和登录卡片中的公告展示；不改变登录、注册、邀请码和管理员联系方式逻辑。

## 视觉与无障碍

- 延续工作台现有 `var(--bg-surface)`、`var(--border-strong)`、`var(--danger)` 和 `var(--text-*)` 设计变量，与积分按钮形成同一组顶栏控件。
- 按钮提供中文 `aria-label`，未读数量通过 `aria-live="polite"` 或等效隐藏文本通知辅助技术用户。
- 浮层使用 `role="dialog"` 与 `aria-label="站点公告"`；关闭按钮有明确的中文标签。
- 角标不承担唯一信息传达职责，屏幕阅读器可获得未读公告数量。
- 角标和铃铛动效只使用 transform/opacity 等低成本属性，并在减少动画偏好下关闭。

## 测试策略

- 为未读数量推导添加单元测试：空列表、全部已读、部分未读和超过 9 条。
- 为公告入口添加组件契约测试或可测试的 UI helper，覆盖铃铛存在、角标文本、点击打开、打开后标记已读和关闭行为。
- 为登录页做源码/契约回归测试，确保不再调用 `/api/public/announcements`，且公告文案块不会渲染。
- 运行现有测试套件、TypeScript 检查、ESLint 和生产构建，确认公告 Tab 与顶栏布局没有回归。

## 非目标

- 不修改公告数据库结构、管理员公告编辑功能和公告 API。
- 不改变公告正文、排序、置顶规则或已读记录的 localStorage 格式。
- 不在登录页增加新的通知入口。
- 不实现声音提醒、通知偏好设置或浏览器系统通知。
