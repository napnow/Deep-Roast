# 管理端用户生图总开关设计

## 目标

管理员可以在“站点与内容 / 站点设置”中关闭普通用户的所有生图能力，同时保留管理员自身的生图与风格测试能力。

## 权限规则

- 新增全局设置 `imageGenerationEnabled`，数据库字段默认为开启。
- 开启时维持现有行为。
- 关闭时，角色为 `user` 的请求不得使用文生图、图生图、批量图生图或 OpenAI 兼容 API Key 生图。
- 角色为 `admin` 的网页请求与 API Key 请求不受影响。
- 反推提示词不生成图片，继续开放。
- 服务端是最终权限边界；前端禁用仅用于改善反馈，不能替代服务端校验。

## 服务端设计

- 在 `site_settings` 增加 `image_generation_enabled integer not null default 1`。
- `getSiteSettings` 和管理端站点设置接口返回 `imageGenerationEnabled`。
- 管理端 `PUT /api/admin/site-settings` 接受布尔字段并持久化。
- 生图服务在实际调用上游和扣积分前统一校验：若开关关闭且调用角色不是 `admin`，抛出状态码 `403`、错误码 `IMAGE_GENERATION_DISABLED`，文案为“生图功能暂时关闭”。
- 校验放在共享生图服务入口，覆盖 `/api/image`、`/api/image-edit`、批量编辑和 `/api/v1/images/generations`，避免遗漏或绕过。

## 前端设计

- `AdminSiteSettingsCard` 在“新用户注册”开关附近增加“用户生图”开关，状态文案为“开放中 / 已关闭”。
- 用户初始配置中返回 `imageGenerationEnabled`。
- 普通用户关闭时，创作面板显示低干扰提示条，生成按钮禁用；管理员不显示限制。
- 即使页面状态未刷新或直接调用接口，服务端仍返回明确的关闭错误。

## 数据迁移与兼容

- 新字段默认值为 `1`，现有部署升级后仍保持生图开启。
- 生产部署前备份数据库；迁移只新增一个非空整数字段，不删除或改写现有数据。
- 生产库迁移历史存在手工基线问题，本次使用经过检查的幂等 `ADD COLUMN IF NOT EXISTS`，不伪造旧迁移记录。

## 测试与验收

- 纯函数测试覆盖：开关开启时用户允许；关闭时普通用户拒绝；关闭时管理员允许。
- 管理端 GET/PUT 能读取和更新开关。
- 普通用户各生图入口关闭时均在上游调用和扣积分前失败。
- 管理员关闭开关后仍可生图。
- 前端禁用状态、提示、错误文案正确。
- 全量测试、TypeScript、定向 ESLint、生产构建通过。
- 部署后检查正式域名 HTTP 200、服务状态 active、数据库字段存在，并保留回滚版本与数据库备份。
