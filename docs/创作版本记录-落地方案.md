# 创作版本记录落地方案

本方案针对第二部分「创作版本记录」。第一部分已上线的图片展示布局保持现状，画布只展示当前选中的作品。本文为方案，尚未实施。

上一轮线上只读核对的基线为 `20.41.121.31:/opt/deeproast-current`，软链当时指向 `/opt/deeproast-releases/20261116-image-canvas`，服务为 `deeproast`。实施前重新核对；本地 `master` 的 `a97154f` 不是线上基线。

## 一、事实与待验证事项

### 只读核对结论

以下是上一轮检查时的观察，不代表此刻线上状态：

- `deeproast` 服务当时为 active、工作目录为 `/opt/deeproast-current`。发布目录没有 `.git`，无法据此确认 Git commit。
- 实际表 `image_generations` 的 `id`、`user_id` 为 UUID，`created_at` 可空，有 `(user_id, created_at)` 索引；尚无来源或版本组字段。
- 生图和编辑成功时在图片处理与文件写入后插入作品并返回 ID。批量通过 `runImageEditTasks` 执行，每张成功结果分别入库，返回成功、失败计数。
- `POST /api/image-edit` 和 `POST /api/image-edit/batch` 均认证用户并使用请求幂等；编辑协议有 `per-image` 和 `reference` 模式、明确的目标图，但无来源作品 ID。
- `GET /api/image-history` 默认最近 50 条。删除服务先按作品 ID 和用户 ID 查找，再删除该作品的图片、缩略图及记录。
- 线上已有单图画布与继续修改入口，所选作品会转为图生图草稿；尚未发现持久化来源关系。
- 上一轮本地 `master` HEAD 为 `a97154fe8983b2c976c45f00007db5b8320f41e2`，工作区有未提交改动。线上源码和数据库的模型默认值存在差异，本次不处理。

### 待验证假设

- 发布目录源码与当前 `.next` 构建产物完全对应，需要结合构建和部署记录、关键文件校验；目录名及服务状态不能单独证明。
- 线上迁移执行命令、Drizzle journal/元数据登记、备份恢复机制及实际回滚脚本尚未完整核实。
- 已有目标图可能为私有 URL、旧图片 URL 或上传数据；服务端安全读取已授权原图及传给上游的路径须验证。
- 租约过期、进程崩溃、批量部分成功后的幂等重放尚未完整验证；不能假设现有请求级幂等已经保证每个变体只入库一次。
- 管理员图片清理、账号清理、私有图片访问、所有生图入口、数据量、索引耗时与执行计划需进一步核对。

## 二、数据库与迁移

### 字段与关系

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `source_image_id` | 可空 UUID | 直接父作品；独立起点或无记录上传目标为空。 |
| `version_group_id` | 可空 UUID | 稳定版本组标识，用于从当前作品查询同组作品。 |

- 新独立作品预先生成作品 UUID，令 `version_group_id = id`、`source_image_id = NULL`。
- 新子作品以经过服务端校验的实际目标为父图，组 ID 取目标的 `version_group_id`，为空时取目标 ID。客户端不能指定组 ID。
- 旧作品两个字段继续为空，不回填或推断历史关系；查询时把 `COALESCE(version_group_id, id)` 当组 ID。旧作品可作为新分支起点，多个客户端从同一旧作品创建的分支进入同一组。
- `source_image_id` 不使用级联外键或 `ON DELETE SET NULL`，父图删除后保留原 ID 并标注来源已删除。组 ID 不作为作品外键；根图或中间图删除后，同组存活作品仍可互查。
- 服务端负责用户隔离；账号删除与后台清理的影响须在实施前核验。

### 迁移 SQL 草案

以下未执行。实际迁移编号、登记方式及索引构建方式必须依线上迁移器确认。

```sql
ALTER TABLE image_generations
  ADD COLUMN source_image_id uuid,
  ADD COLUMN version_group_id uuid;

ALTER TABLE image_generations
  ADD CONSTRAINT image_generations_source_not_self
  CHECK (source_image_id IS NULL OR source_image_id <> id);

CREATE INDEX image_generations_user_version_group_idx
  ON image_generations (
    user_id,
    (COALESCE(version_group_id, id)),
    (COALESCE(created_at, TIMESTAMP '1970-01-01 00:00:00')) DESC,
    id DESC
  );
```

同步修改线上基线的 `src/db/schema.ts`，核对迁移文件与 Drizzle 元数据。在生产规模副本测量锁等待、索引体积与执行计划；若选择 `CREATE INDEX CONCURRENTLY`，须拆出事务，处理失败留下的无效索引，并在索引有效后才宣告迁移完成。

### 兼容和回滚

常规回滚采用**回滚代码、保留数据库字段**：旧代码忽略可空字段，已写入关系仍保留。回滚期间旧代码创建的作品无已知关系，之后按旧作品处理，无法还原其隐含关系。

若确需删除字段，先备份作品 ID 与关系数据，确认所有实例和任务不再依赖字段，再移除索引、约束和字段；该操作会丢失关系，不作为常规回滚。迁移登记回退方式按实际迁移器确认。

## 三、接口改动

### 单张和批量编辑

保留 `POST /api/image-edit` 和 `POST /api/image-edit/batch`。reference 模式为目标增加 `sourceImageId`，per-image 模式在每个目标项增加该字段；上传图无记录则为 `null`。

```json
{
  "mode": "reference",
  "targetImage": "目标图片数据",
  "sourceImageId": "父作品 UUID 或 null",
  "targetIndex": 0,
  "referenceImages": ["其他参考图"],
  "prompt": "修改描述",
  "count": 3
}
```

```json
{
  "mode": "per-image",
  "items": [{
    "image": "目标图片数据",
    "sourceImageId": "对应父作品 UUID 或 null",
    "targetIndex": 0,
    "prompt": "修改描述"
  }]
}
```

1. 从认证会话取得用户 ID；非空来源按 `id + user_id` 校验。非法 UUID 返回参数错误；不存在、已删除或属于其他用户统一返回不可用，避免泄露记录存在性。
2. 有来源时，服务端从已授权作品安全解析并读取真正的目标图，不能验证 ID 后仍信任客户端提交的另一张目标图。其他参考图沿用现有验证方式。
3. 无记录的上传目标传空来源，每张成功结果各为独立起点；其他参考图不能被误认作父图。
4. 接受任务时保存校验后的来源及组 ID，并取得目标图安全快照或句柄，避免跨长时间上游调用持数据库锁。已读取目标后父图被删除，任务可继续，成功结果保留来源 ID 并标注来源已删除；读取前被删则返回目标不可用。快照生命周期、大小及清理需验证。
5. 成功作品元数据、来源及组 ID 在同一次插入中写入；失败变体不建记录。核对写库失败的文件清理及积分退款。
6. 验证请求幂等、租约和批量恢复，并为任务及变体设计稳定去重，覆盖成功入库后进程崩溃、重放及部分失败。

成功响应沿用 `images`、`total`、`succeeded`、`failed`，每个成功项增加 `sourceImageId`、`versionGroupId`。旧客户端不传来源时按无已知来源处理。

### 版本列表

新增 `GET /api/image-history/{id}/versions?limit=50&cursor=...`：

1. 登录后按 `id + user_id` 查当前作品，不存在或非本人统一 404。
2. 计算 `groupId = COALESCE(version_group_id, id)`，仅查询当前用户同组作品。
3. 默认 50 条、限制上限；按 `(COALESCE(created_at, 1970-01-01), id)` 倒序。游标包含时间和 ID，校验格式及查询范围，后续页使用严格小于条件。
4. 批量在当前用户范围判断父图是否存在，返回 `sourceStatus`：`none` 无已知来源，`available` 存在，`deleted` 有来源 ID 但本人父图不存在。
5. 复用历史接口的私有图片和旧图 URL 转换，避免逐条查询父图。

```json
{
  "items": [{
    "id": "作品 UUID",
    "sourceImageId": "父作品 UUID 或 null",
    "sourceStatus": "available",
    "versionGroupId": "版本组 UUID",
    "imageUrl": "受保护图片地址",
    "thumbUrl": "可选缩略图地址",
    "createdAt": "时间或 null"
  }],
  "nextCursor": "游标或 null"
}
```

`GET /api/image-history` 仍默认最近 50 条，扩充字段兼容旧前端；版本列表独立查询。`DELETE /api/image-history/{id}` 仅删除选中作品和文件，实际删除条件也应包含用户 ID；删除后刷新版本列表。需验证文件读取与删除并发。

## 五、分阶段实施与验收

### 阶段 0：确认基线

从线上发布目录建立隔离实施副本，核对源码与构建产物、部署记录、迁移器、备份及全部生图路径，保留本地未提交改动。

**验收：**证明副本对应线上发布内容并记录本地差异；隔离环境复现当前编辑、批量、历史和删除；迁移草案按真实机制复核。

### 阶段 1：迁移及服务端写入

实现兼容迁移和 schema，绑定及校验目标，成功入库时写关系，处理重放、退款与文件清理。

**验收：**

- 用户隔离：他人、已删除和不存在的来源被拒绝，响应不泄露他人记录；伪造本人来源 ID 加另一张图时使用服务端已授权作品。
- 批量部分失败：成功作品数等于成功变体数，每张指向正确父图；失败不建记录。幂等重放、成功入库后崩溃恢复不重复、不丢失已成功结果。
- 多图与旧作品：仅实际目标成为父图；无记录上传目标成为独立起点；旧作品无虚构来源，可作为新分支起点，同一旧图的新分支同组。
- 并发：目标读取前和读取后分别删除父图，结果符合第三节规则；生成期间不长期持数据库锁。

### 阶段 2：版本查询与删除

实现当前作品鉴权、同组分页、来源状态和单作品删除。

**验收：**

- 父图删除：删除根图、中间图及叶图后，其余记录和图片保留；子图标注来源已删除，仍可查看及继续修改；任意存活版本可查询同组存活作品。
- 分页与隔离：超过 50 张可逐页找到旧版本；相同或空时间戳与分页边界不重复、不遗漏；不能查询或推断他人作品和父图状态。
- 旧数据：旧图正常打开、删除并作为分支起点；私有图片与旧图访问控制保持有效。

### 阶段 3：前端交互

完成带作品 ID 的草稿、侧边版本列表、切换、继续修改、分页与删除状态，保持现有单图画布。

**验收：**多参考图、目标切换、移除槽位及上传混用时父图正确；成功变体可单独切换、从任意版本继续修改；刷新和另一设备登录后可找回。慢请求、请求失败、账号切换及删除当前作品不串状态、不误报丢失。

### 阶段 4：预发布与上线验收

在生产规模副本演练迁移、索引、备份恢复和代码回滚；在独立构建环境完成构建测试，再按第六节上线。

**验收：**迁移、健康检查及服务日志正常；授权测试账号复核用户隔离、批量部分失败、父图删除、旧数据、超过 50 条分页及跨设备恢复；监控幂等、退款及文件清理。

## 六、风险、上线与回滚顺序

**关键风险：**新代码先于数据库迁移运行会因缺列导致查询或写入失败。先增加可空字段再部署新代码，旧代码仍可运行。还需验证长任务期间删除父图、部分成功重放、索引锁等待、旧图权限、账号切换和后台清理。

1. **上线前：**重新确认线上版本、服务配置、迁移登记和可用回滚包；验证备份可恢复；在生产规模副本演练迁移、索引及回滚。在其他机器构建，避免在内存紧张的生产机上构建。
2. **先迁移数据库：**新增可空字段、约束和索引，按真实迁移机制登记。迁移和代码部署属于同一次受控发布。
3. **确认迁移：**检查字段、约束、有效索引和迁移登记；如失败或索引无效则停止，不能切换到依赖新字段的代码。
4. **再部署代码：**切换服务并检查健康，使用授权测试账号验收，观察生图、版本查询、幂等、退款及清理日志。遵循既有自动清理规则，不手动清 release 目录。
5. **故障回滚：**先切回已验证的旧发布版本并确认服务恢复，保留数据库新增字段及关系。回滚期间旧代码新建作品按无已知来源的旧作品处理；仅在备份并明确决策后考虑删除字段。

本文未执行生产迁移、部署或回滚；最终命令与操作窗口应依据实施前只读核对和演练确定。
